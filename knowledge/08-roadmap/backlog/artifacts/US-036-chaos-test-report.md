# US-036 Chaos Test Report — GitHub Connector Unavailable

**Status:** Filed · **Date:** 2026-07-29  
**Story:** US-036 / NFR-005  
**Package:** PI-2 exit review

---

## 1. Objective

Prove graceful degradation: when the GitHub source connector is unavailable, queries that would normally use GitHub content still return a **partial wiki-backed answer** with `source_availability_warning: ["github-unavailable"]` and **do not fail with 5xx**.

## 2. Procedure

1. Confirm both GitHub and wiki sources are indexed and healthy.
2. Simulate GitHub API token revocation:
   - Set `CHAOS_GITHUB_UNAVAILABLE=true`, **or**
   - Set `GITHUB_PAT=revoked`, **or**
   - Update the GitHub source `secret_reference` to contain `revoked`.
3. Submit a query that normally spans GitHub + wiki content (e.g. authentication middleware).
4. Assert response shape and status.
5. Restore the GitHub token / clear chaos flag; confirm normal dual-source retrieval resumes.
6. File this report with the PI-2 exit package.

Automation:

```bash
python scripts/chaos/run_chaos_github.py
# pytest coverage:
python3 -m pytest backend/tests/test_us036_cost_slo_chaos.py -v
python3 -m pytest agent/tests/test_us036_source_availability.py -v
```

## 4. Implementation notes

- `ConnectorUnavailableError` caught per connector in `source_availability_service.py`.
- `HybridRetrievalEngine.retrieve_with_availability()` excludes unavailable source IDs and returns warnings.
- Knowledge + Agent responses expose `source_availability_warning` without elevating to 5xx.
